# 폴더 구조 규칙

ToteDB의 소스, 시험, 문서와 빌드 산출물을 두는 자리다. 구성 요소의 호출 관계는 [아키텍처](../architecture.md)에 있다.

## 폴더

| 위치 | 내용 |
|---|---|
| `include/` | 외부에서 쓰는 C 헤더와 모듈별 공개 선언 |
| `src/storage/` | 페이지 파일, 행·값 인코딩, 카탈로그, 색인, 트랜잭션 |
| `src/sql/` | lexer, 문장 구조, 식 평가, SQL 실행, 세션, 결과 |
| `src/queue/` | 선택형 ACK 큐와 큐 시험 빌드 규칙 |
| `src/capi/` | 다른 언어가 호출하는 평탄한 C API |
| `python/totedb/` | ctypes 기반 Python 패키지 |
| `tests/` | C·Python 시험, 실패 주입, SQL 비교, 패키지 검사 |
| `bench/` | 입력과 결과를 대조하는 성능 측정 도구 |
| `examples/outbox/` | Python 생산자와 C worker가 같은 큐를 쓰는 예제 |
| `docs/` | 아키텍처, 빌드와 시험, 안전성 결과, 출처 |
| `.github/` | 기여 안내와 CI·릴리스 워크플로 |
| `.devcontainer/` | Linux 개발 환경 |
| `build/` | 빌드·시험 산출물. Git 추적 제외 |

## 파일

C·Python 소스는 언어 관례에 따라 snake_case로 짓는다. 문서 이름은 영어 소문자 kebab-case를 쓴다. `README.md`, `Makefile`, `pyproject.toml`처럼 도구가 정한 이름은 유지한다.

공개 헤더는 `include/`에 두고 구현 전용 헤더는 사용하는 모듈 안에 둔다. 모듈의 책임과 다른 파일을 편의상 한 폴더에 모으지 않는다. 함수와 타입을 옮길 때는 호출자와 빌드 입력을 함께 확인한다.

새 시험은 검사 대상이 속한 `tests/test_*` 묶음에 둔다. 새 측정 도구는 `bench/`에 두고 입력 조건과 결과 판정 방법을 명시한다. 시험 결과 JSON은 빌드 폴더에 둔다.

## 문서와 산출물

문서는 [문서 목록](../README.md)에 연결한다. 현재 사용법과 과거 검증 기록을 구분한다. README는 설치와 첫 실행을 설명하고 세부 내용은 해당 문서로 연결한다.

빌드 산출물, 캐시, 시험 DB, 가상 환경과 배포 파일은 `.gitignore`의 제외 경로에 둔다. 이미 추적 중인 사용자 파일이나 실행 중인 시험의 데이터를 일괄 삭제하지 않는다.
