# C 코딩 규칙

C 코어와 공개 헤더에 적용하는 규칙이다. 빌드·시험 명령은 [빌드와 시험](../build-and-test.md)에 있다.

## 형식과 이름

들여쓰기는 공백 4칸을 쓴다. 함수 정의의 여는 중괄호는 다음 줄에 놓고, 제어문과 구조체의 여는 중괄호는 같은 줄에 놓는다. 수정하는 코드의 형식을 따른다.

| 대상 | 형식 | 예 |
|---|---|---|
| 함수와 변수 | snake_case | `page_file_open`, `page_count` |
| 타입 | snake_case와 `_t` 접미사 | `page_file_t`, `value_view_t` |
| 상수와 enum 값 | UPPER_SNAKE_CASE | `PAGE_FILE_OK`, `TOTE_BUSY` |
| 파일 | snake_case | `page_file.c`, `ack_queue.h` |

이름에 크기와 시간의 단위를 드러낸다. 바이트 수와 원소 수, 페이지 번호와 행 참조를 같은 값으로 다루지 않는다. 비교는 `size == 0`, `ptr == NULL`처럼 대상 값을 먼저 쓴다.

## 모듈 경계

외부에서 쓰는 선언은 `include/`에 두고, 구현 파일끼리 공유하는 선언은 해당 `src/` 모듈에 둔다. 파일 안에서만 쓰는 함수는 `static`으로 선언한다.

`include/totedb.h`는 다른 언어 바인딩이 호출하는 평탄한 C API다. DB 코어는 큐 모듈을 참조하지 않는다. 큐는 세션의 SQL·트랜잭션 API를 통해 데이터를 바꾼다. 구성 요소별 책임은 [아키텍처](../architecture.md)에 있다.

## 메모리와 자원

메모리를 반환하는 API는 누가 해제하는지와 유효 기간을 헤더에 적는다. 소유한 버퍼와 빌린 버퍼를 구분하고, 빌린 메모리를 해제하지 않는다. 크기를 곱하거나 더하기 전에 정수 범위를 확인한다.

할당 실패, 파일 열기·읽기·쓰기·동기화 실패를 호출자에게 전달한다. 성공·실패·결과 불확실을 구분하고, 실패 뒤 핸들을 다시 쓸 수 있는지 명시한다. 결과가 불확실한 commit을 실패로 단정해 재시도하지 않는다.

함수는 자원을 얻은 순서의 역순으로 정리한다. 여러 실패 경로가 같은 정리를 공유하면 정리 레이블을 쓴다. 오류 경로에서도 잠금, 파일, 버퍼와 메모리 예산을 반환한다.

## 공유 상태와 저장

잠금 책임과 핸들의 프로세스·스레드 경계를 지킨다. 게시된 페이지를 제자리에서 고치지 않는다. 세대 게시, 페이지 회수 지연, fork한 자식의 핸들 거절 규칙은 [아키텍처의 지켜야 할 규칙](../architecture.md#지켜야-할-규칙)을 따른다.

외부 입력은 길이·형식·범위를 확인한 뒤 내부 값으로 바꾼다. SQL 매개변수는 문자열 연결 대신 binding으로 받는다. 디스크 형식은 포인터나 구조체 메모리를 그대로 저장하지 않고 명시적으로 인코딩한다.

## 주석과 시험

주석에는 공개 API의 소유권·수명·실패 계약이나 외부 동작 때문에 필요한 제약을 적는다. 코드만 읽어도 알 수 있는 처리 순서는 되풀이하지 않는다. 미완성 작업은 이슈로 추적한다.

시험은 `tests/test_*.c`에 둔다. 성공 경로와 입력 경계, 할당·I/O 실패 뒤 상태, 다시 열기 뒤 데이터를 확인한다. 결함을 고쳤으면 수정 전 실패와 수정 후 통과를 구분한다. 직접 실행하지 않은 검사를 통과로 적지 않는다.

`Makefile`의 `-Wall -Wextra -Werror` 경고를 없앤다. sanitizer별 검사와 실행 환경은 [빌드와 시험](../build-and-test.md#ci)에 있다.
