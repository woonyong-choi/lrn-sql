# Python 코딩 규칙

Python 바인딩, 시험 도구, 예제와 측정 스크립트에 적용하는 규칙이다. 지원 버전은 `pyproject.toml`의 Python 3.9 이상이다.

## 형식과 이름

들여쓰기는 공백 4칸을 쓴다. 함수·변수·모듈은 snake_case, 클래스는 PascalCase, 상수는 UPPER_SNAKE_CASE로 짓는다. 비공개 이름 앞에는 `_`를 붙인다. 함수 인자와 반환값에는 타입 힌트를 적는다.

import는 표준 라이브러리, 외부 패키지, 같은 프로젝트 순서로 묶는다. 그룹 사이에는 빈 줄을 둔다. 바인딩은 Python 3.9에서 불러올 수 있는 문법과 표준 라이브러리 API를 쓴다.

현재 저장소에는 Ruff·Black·mypy 설정이 없다. 예시 설정을 실제 검사 기준으로 취급하지 않는다. CI가 실행하는 명령은 [기여 안내](../../.github/CONTRIBUTING.md#검사)에 있다.

## 바인딩 경계

공개 패키지는 `python/totedb/`에 둔다. ctypes 선언과 공유 라이브러리 탐색은 `_native.py`에서 관리한다. DB·트랜잭션·큐 동작은 C 코어를 호출하고 바인딩에 따로 구현하지 않는다.

C에 넘기는 바이트 버퍼의 길이와 수명을 보존한다. Python 객체를 돌려주기 전에 C 결과를 복사해야 하는지, 해제 함수를 누가 호출하는지 확인한다. C 상태 코드는 `errors.py`의 예외로 변환한다.

DB와 트랜잭션 수명은 `with` 문으로 관리한다. `BusyError`의 재시도는 지정한 시간 한도를 지키고, commit 결과가 불확실한 오류를 일반 재시도로 처리하지 않는다.

## 오류와 출력

복구할 수 없는 오류는 예외로 전달한다. 예외를 무시하거나 실패한 입력을 성공 결과로 바꾸지 않는다. 원인을 바꿔 전달할 때는 예외 연결을 유지한다. 실행 도구는 실패를 0이 아닌 종료 코드로 알린다.

진단과 정상 결과를 구분한다. 라이브러리는 호출자가 로그를 설정하게 한다. 경로·SQL·payload에 포함된 사용자 데이터를 진단에 불필요하게 넣지 않는다.

## 시험과 측정

pytest 시험은 `tests/test_*.py`에 둔다. 예상 오류는 `pytest.raises`로 확인한다. 성공뿐 아니라 잘못된 인자, 실패 뒤 다음 호출, 자원 해제, 다시 열기 뒤 상태를 검사한다.

SQL 비교에서는 같은 입력의 행·오류·변경 행 수를 대조한다. 선언한 엔진 간 의미 차이, 실패, 실행하지 않은 검사를 구분한다. PostgreSQL 연결 설정이 없을 때의 생략을 PostgreSQL 통과로 기록하지 않는다.

성능 측정은 입력 크기·seed·반복·내구성 조건을 결과와 함께 남긴다. 다른 조건의 시간으로 배수를 만들지 않는다. 프로세스 강제 종료와 전원 차단의 보장을 구분한다. 측정 도구와 실행 명령은 [빌드와 시험](../build-and-test.md#다른-엔진과-비교)에 있다.
